# دليل تشغيل ZALAM AI — مختبر التقييم الأمني

هذا الدليل يوضح تشغيل الوظائف الموجودة فعليًا، ويفصلها عن القدرات المخطط لها.

## متطلبات التشغيل
- Node.js 20 أو أحدث.
- تثبيت الحزم بواسطة `npm install`.
- إعداد مزوّد متوافق مع OpenAI عبر متغيرات البيئة الموضحة في `.env.example`.
- إعداد رمز وصول قوي وفريد في `ZALAM_ACCESS_TOKEN` بطول 24 حرفًا على الأقل.
- لا تضع الأسرار في GitHub أو في واجهة المتصفح.

## إعداد الفحص السلبي الحالي
اضبط على الخادم:
```env
ZALAM_LAB_TARGET_URL=https://lab.example.com
ZALAM_LAB_ALLOWED_HOST=lab.example.com
```
يجب أن يكون المضيف مطابقًا تمامًا، وأن يكون HTTPS، وأن يحل DNS إلى عناوين عامة. لا تستخدم نطاق جهة خارجية إلا بتفويض مكتوب يحدد الاختبار. الفحص الحالي يرسل HEAD ويقرأ ترويسات الاستجابة فقط.

## تشغيل محلي
```bash
npm ci
npm run typecheck
npm run build
npm run dev
```

## استخدام النتائج
1. افتح مساحة العمل وأدخل رمز الوصول.
2. افحص حالة إعداد الخادم.
3. شغّل الفحص السلبي للهدف الذي عيّنه مسؤول المختبر.
4. صدّر نتيجة JSON واحفظها ضمن سجل التقييم.
5. راجع التوصيات يدويًا؛ وجود الترويسة لا يثبت صحة إعدادها.

## حدود مهمة
- الفحص لا يستغل الثغرات ولا يجرب كلمات مرور.
- لا يفحص الشبكات الداخلية أو Wi-Fi أو الهواتف أو التطبيقات البنكية في هذه النسخة.
- لا ينفذ تحويلات مالية ولا يتصل بحسابات حقيقية.
- لا توجد حاليًا قاعدة بيانات تقارير مركزية أو سجل تدقيق متعدد المستخدمين.
- لا تستخدم النتائج كبديل لاختبار اختراق مهني أو مراجعة يدوية.

## بوابة التوسع
قبل إضافة أي ماسح نشط، يجب توفير نطاق مكتوب، قائمة أصول مسموحة، موافقة تشغيل، حد للطلبات، مهلة إيقاف، سجل تدقيق، وهدف تدريبي اصطناعي لاختبار الرفض خارج النطاق.
